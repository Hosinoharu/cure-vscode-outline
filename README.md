# My VSCode Outline Extension

`[d]` 表示默认的 `vscode outline` 具备该功能。

`[x]` 表示使用插件可以实现该功能。

## 关于单个符号

-   `[x]` 点击它时，自动展开其子项（*跳转到对应的位置*是必备的基础功能）
-   `[x]` 点击它时，自动移动到视图中间
-   `[x]` 鼠标放在它上面时，可以展示符号所在位置上面的注释
-   `[x]` 同层级最多只能展开一个。点击其它符号时，能自动折叠同层级的符号
-   `[x]` 可标记，方便多个符号之间来回跳转，类似书签功能
-   `[x]` 可配置，展开它时，自动在编辑器中展开对应的代码块



## 关于整体

-   `[d,x]` 可搜索，默认可以按 `ctrl+p` 然后按 `@` 搜索当前文件的符号，所以不需要单独开发搜索功能。才...才不是偷懒呢！
-   `[d,x]` 可排序，按符号位置、名称、种类
-   `[d,x]` 可过滤，默认 vscode outline 的过滤选项在配置页中，插件只提供了最常见的几个，如*不显示局部变量*

## 响应编辑器的操作

-   `[x]` `follow viewport`：随着编辑器滚动而滚动，始终显示当前视口上下的符号，类似 `minimap`

    -   因为 `vscode TreeView API` 的限制，可以粗糙的实现这种效果，勉强可用

-   `[d,x]` `follow cursor`：鼠标点在哪里，就显示最近的符号并让其滚动到视图中间展示

    -   `vscode outline` 具备该功能，但不会自动折叠，导致展开的符号越来越多
    -   因为 `vscode TreeView API` 的限制，不能让符号自动居中（否则会丢失光标），可以显示鼠标当前所在的符号，_可以同时高亮两个符号表明鼠标位于它们中间_

-   `[x]` 解析自定义的注释，类似书签功能，比如 `#cure-xxx` 可以解析出 `xxx` 部分作为书签

因为 `vscode TreeView` 没有丰富的 `API`，所以在*响应编辑器中的操作*时虽然可以实现期望的功能，但呈现效果仅仅勉强可用。

# dev

开发时不会使用 `webpack` 打包，直接按 `F5` 进行编译和测试，生成的文件在 `/out` 中。
打包插件时才会使用 `webpack` 打包哟，执行命令 `vsce package` 进行打包，生成的文件在 `/dist` 中。
