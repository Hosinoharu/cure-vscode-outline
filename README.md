My VSCode Outline Extension!

# 我想要的 Outline 功能

`[d]` 表示默认的 `vscode outline` 具备该功能。

`[x]` 表示使用 `vscode TreeView` 开发插件可以实现该功能。

## 关于单个符号

- `[x]` 点击它时，自动展开其子项（*跳转到对应的位置*是必须具备的功能）
- `[x]` 点击它时，自动滚动到视图中间
- `[x]` 鼠标放在它上面时，可以展示符号所在位置上面的注释
- `[x]` 可配置，同层级最多只能展开一个
- `[x]` 可标记，方便多个符号之间来回跳转，类似书签功能

## 关于整体

- `[d,x]` 可搜索，默认可以按 `ctrl+p` 然后按 `@` 搜索当前文件的符号，所以不需要单独开发搜索功能
- `[d,x]` 可排序，按符号位置、名称、种类
- `[d,x]` 可过滤，默认的过滤选项在配置页中，我只需要最常见的几个，如*不显示局部变量*

## 响应编辑器的操作

- `[x]` `follow viewport`：随着编辑器滚动而滚动，始终显示当前视口上下的符号，类似 `minimap`
    - 因为 `vscode TreeView API` 的限制，可以粗糙的实现这种效果，勉强可用吧

- `[d,x]` `follow cursor`：鼠标点在哪里，就显示最近的符号并让其滚动到视图中间展示
  - `vscode outline` 具备该功能，但不会自动折叠，导致展开的符号越来越多
  - 因为 `vscode TreeView API` 的限制，不能让符号自动居中（否则会丢失光标），但可以显示鼠标当前所在的符号。*可以高亮两个表明鼠标位于两个符号中间*
- `[x]` 解析自定义的注释，类似书签功能，比如 `#cure-xxx` 可以解析出 `xxx` 部分作为标为标签使用

# 最终实现时的考量

因为 `vscode TreeView` 没有丰富的 `API`，所以在*“响应编辑器中的操作”*时虽然可以实现期望的功能，但呈现效果差强人意。

上面所有功能当然可以使用 `WebView` 来实现，并且扩展性也更强，**代价则是**：

- 复杂的代码。因为开发 `ui` 总不能自己从零开始，通常是使用框架如 `vue`
- 与 `vscode ui` 上的差别。比如做符号的 `tooltips` 时，`vscode ui` 自带的效果更好
- 略微增加的响应延迟

我觉得，使用 `WebView` 实在是有点浪费了，不如给 `vscode` 提交 `issue` 让它们增加 `TreeView API`。
